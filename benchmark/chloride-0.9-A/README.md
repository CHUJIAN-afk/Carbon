# 0.9-A Chloride 兼容性验证

## 修复范围

1.20.1 的 Carbon 与 Chloride 都使用 Redirect 接管 `ClientLevel.entitiesForRendering()`，联装 Embeddium 0.3.31、Chloride 1.8.1 时出现 `@Redirect conflict`。改为可组合的 WrapOperation，并在 Forge 发布包中内置 MixinExtras 0.3.5。

1.21.1 原有收集发生在 Chloride 返回最终实体列表之前。0.9 中把 Chloride 的实体数量限制设为 128 或 0，仍绘制缓存中的 678 个实例。现在先完成外部筛选，再收集掉落物；三分支均比较筛选列表，在列表变化时更新场景及队列。

本机 0.9 与 Chloride 1.8.1 的默认组合仍能实例化，未复现默认配置下完全失效。本次确认并修复的是入口冲突、收集顺序和筛选变化后的缓存失效问题。

## 条件

1000 个普通掉落物实体，包含 480 把下界合金剑与 520 个石头，落在石质平台上，禁止合并和拾取。玩家位置 `(0.5, 200, -9.5)`，水平朝向物品，最近一行约 10.5 格。保留掉落物距离限制，因此默认提交其中 678 个实例。

960×540，60 FPS 上限，窗口在后台隐藏，正常 tick，无光影。Carbon 默认启用专用管线、跳过视锥检查和 2 ms 更新预算，物理化默认关闭。测试仅检查实例化有效性，不采集帧率收益。

| 游戏版本 | 加载器 | 渲染模组 | Chloride | 默认实例数 / 实例化绘制 | OpenGL 错误 |
| --- | --- | --- | --- | ---: | ---: |
| 1.20.1 | Forge 47.4.22 | Embeddium 0.3.31 | 1.8.1 | 678 / 2 | 0 |
| 1.21.1 | NeoForge 21.1.238 | Sodium 0.8.13 | 1.8.1 | 678 / 2 | 0 |
| 26.1.2 | NeoForge 26.1.2.108 | Sodium 0.9.2 | 1.8.1 | 678 / 2 | 0 |

三个组合均未出现 Redirect 冲突或实例化回退。1.20.1 的第三方发布包在开发环境中转换为官方映射后运行；Carbon 发布 Jar 仍使用 Forge 生产映射。另将最终 Forge 发布包转换至开发映射，移除 Embeddium 与 Chloride 后加载，确认内置 MixinExtras 可独立初始化，仍得到 678 个实例、2 次实例化绘制及 0 个 OpenGL 错误。

## 筛选回归

三分支均在运行中直接调整 Chloride 配置字段，未手动设置 Carbon 的缓存失效标志。

| Chloride 实体数量限制 | 物品实例数 | 实例化绘制 | 圆形阴影实例 |
| --- | ---: | ---: | ---: |
| 512（无限制） | 678 | 2 | 1060 |
| 128 | 127 | 2 | 203 |
| 0 | 0 | 0 | 0 |
| 恢复 512 | 678 | 2 | 1060 |

128 的限制同时包含玩家实体，所以物品数为 127。各阶段 OpenGL 错误均为 0。1.21.1 另验证 Chloride 1.7.7 与 Sodium 0.6.13，默认同样为 678 个实例、2 次实例化绘制。
