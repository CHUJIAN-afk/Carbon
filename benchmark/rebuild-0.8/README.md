# 0.8 重建性能与代码审阅

这是最终定稿前的历史实验；当前默认值、开关语义及最终成绩以 [0.8 最终对照](../final-0.8/README.md) 为准。

本次保留单遍实体收集，并缓存同一实体 tick 内的接管资格和真实燃烧状态。正式对照中，每帧强制重建的 collect p95 从 **2.6165 ms 降至 2.4015 ms（约 8.2%）**；但其他三组的平均 FPS 和 1% low 均低于基线，不能据此宣称整体 low 帧稳定改善或周期跳变已消除。

## 方法

硬件为 Intel Core i7-12800HX、NVIDIA GeForce RTX 4070 Laptop GPU。Minecraft 1.21.1、NeoForge 21.1.238、Sodium 0.8.13、Lithium 0.15.4、JetBrains Runtime 21.0.11；实际全屏 **2560×1600，FOV 70**。Carbon 使用默认非物理化渲染、`skipVisibilityChecks=false`；实体距离设为 200%，保证完整布局处于距离范围内。

本轮未进行 NeoForge 21.1.0 的最低版本启动验证。

10000 个不可堆叠的下界合金剑实体密排在地面，正常重力与碰撞标志，全部落地。玩家固定于 `(0,200,-10)`，平视；最近实体距离 11.00009 格。固定/小幅转向/强制重建组均收集 10000 个物品，边缘转向组的可见数量为 7838–10000。

正式测试**客户端和服务端均冻结 tick**，用于隔离渲染与缓存重建成本；产品没有针对冻结 tick 的快速路径，测试辅助模组也不取消物品 tick。该结果不能代表正常游戏中 10000 个实体持续更新时的整体帧率。

每版每模式各取一次连续 20 秒样本。只有 `GLFW_FOCUSED=true` 才开始计时；记录中失焦会丢弃整段并重新等待焦点。八段正式样本均 `continuousFocus=true`、`focusRestarts=0`、`completedTargetDuration=true`，末次场景检查窗口可见、未最小化、OpenGL 错误为 0。帧数据先缓存在内存，结束后写出。

基线为 `0c1ba0b` 的保存快照：renderer 字节码已与直接编译该提交的结果核对一致，仅额外保留低频 yaw/age 失效 hook。本次使用当前主分支候选源码，三个产品文件按 LF 统一换行后的 SHA-256 与构建产物哈希记录在 [results.json](results.json)。

四种模式：固定视角；按客户端 tick 更新的 `yaw=5×sin(秒数)`；每帧标记场景过期以强制完整重建；`yaw=45×sin(秒数)` 穿过视锥边缘。相机转动仍执行正常剔除。

正式窗口未出现早期 PixelSky 额外占用约一个 CPU 核心的情况，但仍有残余负载差异，尤其小幅转向组 PixelSky 为 13.6% / 19.4%。强制组 GPU 平均时钟为 2210 / 2490 MHz，利用率约 34% / 39%，主要受 CPU 限制；这仍不是完全一致的硬件状态。两版冻结时的游戏时间和物品动画相位也不同。仅一次 20 秒对照不足以建立统计显著性或长期稳定性结论，不能把全部帧率变化直接归于本次代码。

## 审阅与保留的修改

- 每实体缓存接管资格与真实火焰状态，以 `tickCount`、`ItemStack` 引用和组件版本为缓存键。同 tick 的多次重建复用这些非相机数据；同步实体数据、NBT/寿命入口和燃烧正数状态跨界会立即失效。无火冷却计数在负数与零间变化不会反复标脏场景。
- 场景复用核对相机位置、矩阵及相机实体，避免同朝向平移仍错误使用旧可见集合；清理时释放相机实体引用。
- 补充物理 yaw、寿命、动态光效/显式 glint override、GUI foil tick 和动画时钟日界的失效条件；仅开启跳过可见性检查时才计算距离裕量，省去默认路径的重复开方。
- 保留方块光照和阴影接收面缓存的方块、光照、区块失效信号。曾提出的“普通昼夜变化导致阴影接收面陈旧”判断撤回：1.21.1 客户端无参整数 `getSkyDarken()` 不随普通昼夜更新，原版阴影也使用同一原始亮度 API；额外天空暗度 guard 仅作为其他模组主动更新该整数时的兼容保护。

早期 JFR 将防火组件查询定位为约 45% 的 Render thread 执行采样；原始火焰标志短路可消除这条查询链，但该比例不是总耗时节省。后续 JFR 同时显示阴影接收面查找仍有成本，阴影实例写入本身未成为主要热点。本次未加入复杂的阴影字节片段缓存。

## 正确性验证

- 正常 tick 静止场景另做 5 秒 smoke：3843 帧、0 次重建，客户端/服务端均未冻结，物品正常重力与碰撞，OpenGL 错误为 0。仅用于确认正常更新与缓存行为，未形成正常 tick 的旧/新性能对照。
- 10000 个基础物品外加入燃烧铁剑和防火下界合金剑时，专用接管计数为 10001；冻结期间给铁剑添加 `FIRE_RESISTANT` 组件后立即变为 10002，验证同 tick 组件与燃烧失效。两次检查均无 OpenGL 错误。
- 同一最终相机位置 guard 的运行检查：yaw 45°，玩家 X 从 0 平移到 4，接管数从 8760 更新为 10000。

上述场景快照保存在 JSON 的 `validation` 中。

## 撤回与未采用的实验

- 撤回此前本轮 0.8 中标为“正常 tick”的性能结论：旧 `film-capture-helper` 对无重力物品直接取消实体 tick，不能证明正常物品更新的表现。
- 可见集合预检、`visibleItems` 重建及自适应变体在边缘视角出现低帧退化，均已拒绝并从产品撤除；正式结果使用单遍收集方案。
- 未验证焦点、分辨率不同或 PixelSky 明显争用的旧样本不用于本次正式性能结论。

量化摘要、实际场景状态、噪声摘要与本地原始文件路径均归档在 [results.json](results.json)。大体积 CSV/JFR 留在本机忽略目录 `build/rebuild-probe/`，不随此报告提交。
