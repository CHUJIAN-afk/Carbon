# 0.9 拾取动画与落地姿态修复

拾取粒子使用 `ItemEntity.copy()` 创建临时实体，再向实体渲染器传入逐帧向玩家移动的坐标。专用掉落物管线此前仅检查实体所属世界，误将这些副本当作世界实体，并按实体保存的原位置生成实例，丢弃拾取动画传入的坐标。最后一个同类物品移除后，空批次尤其容易接管该副本。

专用模型与圆形阴影现在都只接管世界中注册的原实体；拾取副本保留原版动画提交坐标。通用模型实例化仍可复用调用方传入的完整姿态，不固定动画位置。

落地处理参考 [ItemPhysic Lite 1.21](https://github.com/CreativeMD/ItemPhysicLite/blob/1.21/src/main/java/team/creative/itemphysiclite/ItemPhysicLite.java)：平面物品落地后立即平放，立体物品停止翻滚并保持着地朝向。移除静止后逐 tick 向整圈角度收敛的平滑回正；保留空中翻滚与水、熔岩内的减速。

## 定点回归

Minecraft 1.21.1、NeoForge 21.1.238、Sodium 0.6.13、Iris 1.8.12；隐藏窗口、60 FPS。通过 `ClientPacketListener.handleTakeItemEntity()` 触发原版拾取粒子，观察最后一个同类物品被移除后的实际提交路径。光影场景使用 Complementary Reimagined 5.8.1，先预热程序再记录轨迹。

| 场景 | 修复前副本被专用模型接管 | 修复后 | 修复后记录到的动画位置 |
| --- | ---: | ---: | ---: |
| 物理化开启、无光影 | 9 / 9 次 | 0 / 18 次检查 | 9 个 |
| 物理化关闭、无光影 | 9 / 9 次 | 0 / 18 次检查 | 9 个 |
| 物理化开启、有光影 | 未采集 | 0 / 18 次检查 | 9 个 |

修复后每帧可能依次经过调度器与物品渲染器两个接管检查，所以 18 次检查对应 9 个动画位置。三个场景的水平相机距离均从约 5.8 格缩短至不足 1.2 格，动画位置沿原版提交路径向玩家推进。无光影场景另有每组 9 次圆形阴影检查，均未接管拾取副本。

落地测试预置翻滚角与角速度，并在接地后持续记录：修复前平面和立体物品都从 `roll=0.87` 逐 tick 收敛，存在持续回正；修复后平面物品为 `roll=0, rate=0`，立体物品为 `roll=0.87, rate=0`，各 43 个样本保持一致。

构建 `gradlew.bat build --offline --max-workers=2` 通过，Jar 不含测试辅助模组。结构化记录见 [results.json](results.json)。本次没有重跑帧率对照，也不据此声明性能提升。
