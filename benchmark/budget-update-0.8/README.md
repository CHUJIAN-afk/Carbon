# 0.8 分帧缓存更新：单次性能测试

这是最终定稿前的历史实验；当前默认值、开关语义及最终成绩以 [0.8 最终对照](../final-0.8/README.md) 为准。

新增 `cacheUpdateBudgetMs`，默认 `2.0`，范围 `0.0–20.0`，单位为毫秒。过期场景中的掉落物进入队列，处理时间达到预算后，剩余物品留到下一帧。设为 0 时当帧处理完队列。

实例和阴影各保留一份正在绘制的数据及一份正在更新的数据；更新期间绘制旧场景，整批完成后一起切换，避免绘制不完整的重建结果。普通实体继续从当前实体集合交给原有管线处理。队列中的实体变化会触发后续更新，不因相机持续转动而反复清空队列；关闭管线、调试碰撞箱、资源重载和世界切换会取消旧队列并清理相应数据。

这是协作式 CPU 更新预算，单个物品更新、分配或线程调度可能使耗时超过预算。它不限制整帧时间，也不包含绘制、GPU 上传或交还普通实体的遍历成本。新出现、移除、改变状态或刚进入视锥的物品可能延后到队列完成时显示；可设为 0 恢复立即更新。

## 测试条件

仅采集一次连续 30 秒性能样本。`skipVisibilityChecks=false`，`cacheUpdateBudgetMs=2.0`，物理化关闭；客户端和服务端均冻结 tick。10000 个下界合金剑实体全部落地，正常重力与碰撞，玩家固定在 `(0,200,-10)`，最近距离 11.00009 格，pitch 为 0。

为了实际触发过期与重建，相机按客户端 tick 更新 `yaw=5×sin(秒数)`，不强制标脏。物品和玩家位置保持静止。完全静止的冻结场景会持续复用缓存，不能验证更新队列的性能。

Intel Core i7-12800HX、NVIDIA GeForce RTX 4070 Laptop GPU；Minecraft 1.21.1、NeoForge 21.1.238、Sodium 0.8.13、Lithium 0.15.4、JetBrains Runtime 21.0.11。2560×1600 全屏，FOV 70，实体距离 200%，关闭垂直同步，帧率无限制，隐藏 HUD。性能采集只有一次，其余启动仅做功能检查；采集期间持续获得 GLFW 焦点，失焦重启次数为 0。

完整队列时间统计只包含在采集窗口内处理满 10000 个实体的 600 组：134 组用 2 帧、464 组用 3 帧、1 组用 4 帧、1 组用 5 帧。另一组在采集窗口开始前已处理部分物品，不计入完整队列分位数。每帧更新预算分散了工作，未降低一次完整重建的总工作量。

本次没有新增 0 ms 的性能对照；此前完全静止的 0.7/0.8 数据没有重建且开启了跳过剔除，也不能直接比较。这里验证的是分帧执行和当次表现，不能宣称已消除周期性低帧或证明整体 FPS 提升。样本中仍有 17.83 ms 的长帧，预算也存在超时。

## 功能检查

- 极小正预算下，队列跨帧持续推进，期间仍绘制完整旧场景。最终构建移动一个物品，直接读取 GPU 实例缓冲：排队期间校验值与更新前相同，完成后改变，恢复位置后回到原值。
- 在排队期间切换到 0，下一帧清空队列并发布；20 ms 配置在检查中当帧处理完 10000 个物品。随后恢复默认 2 ms，完成分帧发布。
- 冻结时启用一个物品的发光状态，专用管线收集数量变为 9999；恢复后回到 10000。
- 排队时移除一个物品，完成后队列为 0，收集数量正确变为 9999，没有永久保留旧实例。
- 解除冻结做 4 秒功能检查，实体按原版 tick 更新，恢复静止复用，无 OpenGL 错误；这不是额外的性能样本。
- 性能采集后的最终审阅补充固定每批队列的阴影/剔除设置，并将标脏信号清零移到队列准备之前。随后仅做功能回归：跨帧队列中关闭再开启阴影和跳过剔除，完成后仍完整保留 17030 个阴影；单独关闭阴影后正确变为 0，再开启恢复。未追加 FPS 样本，性能构建与最终构建的源码和 Jar 哈希分别记录。
- `gradlew.bat build --offline` 通过。测试后恢复 10000 个落地物品，关闭游戏，恢复原视频辅助模组和原窗口选项，移除临时 Sodium/Lithium 副本。测试配置保留 `skipVisibilityChecks=false`、`cacheUpdateBudgetMs=2.0`。视频工作和其他分支未改动。
