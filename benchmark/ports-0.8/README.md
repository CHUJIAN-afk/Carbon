# 0.8 多版本迁移与实测

已将主分支验收通过的 0.8 迁移到 `1.20.1-forge` 与 `26.1.2-neoforge`，版本分别为 `1.20.1.8`、`26.1.2.8`，主分支保持 `1.21.1.8`。

- 默认保留 0.7 的跳过视锥与遮挡检查行为，渲染距离限制始终有效，仅转向时继续复用场景。
- 过期缓存按队列分帧处理，`cacheUpdateBudgetMs=2.0`，可配置 0–20 ms，0 表示立即完成；实例与阴影准备好后一起切换，等待时继续绘制旧数据。
- 保留按实体 tick 缓存接管资格和燃烧状态、重建间复用光照与阴影接收面，以及相应的失效处理。
- 1.20.1 适配 NBT 数据，补充仅对已有 NBT 的缓存物品检测原地修改，并在独立配置页加入预算滑块。
- 26.1.2 适配新的物品模型状态和 GPU 缓冲接口，不使用旧版渲染 API。
- Forge 最低声明约束为 47.0.0；26.1.2 分支移除必须使用 `.108` 的构建号约束。实际构建和运行分别使用 Forge 47.4.22、NeoForge 26.1.2.108，未额外启动最低声明版本。

## 测试条件

Intel Core i7-12800HX、NVIDIA GeForce RTX 4070 Laptop GPU；Java 分别为 JetBrains Runtime 17.0.14 和 25.0.4。2560×1600，关闭垂直同步和挂机限帧，实体距离 200%，仅 Carbon 与测试辅助模组，没有 Sodium/Lithium 或光影包。

10000 个下界合金剑物品实体全部落地，正常重力与碰撞，玩家在 `(0,200,-10)` 水平观察，最近距离 11.00009 格。每个最终构建各采集一段 30 秒数据：前 15 秒固定视角，后 15 秒小幅转向 ±5°。

26.1.2 使用原版 tick 冻结，并确认客户端和服务端均冻结。1.20.1 没有原版冻结命令，独立测试模组通过显式开关冻结客户端世界 tick、实体 tick 和服务端世界 tick；不使用无重力物品的 tick 快速路径。测试辅助不包含在发布 Jar 中。

**以下成绩受到并行任务干扰，只保留为当次原始实测，不是干净的优化收益对照。** 采样前检查了进程占用并等待负载回落，但采样过程中后台渲染或编码任务再次启动。按本次单次采样安排，不再追加循环测量。

## 原始成绩

| 分支 | 平均 FPS | 1% low | 0.1% low | 最长帧 |
| --- | ---: | ---: | ---: | ---: |
| 1.20.1 Forge 0.8 | 824.45 | 177.80 | 126.91 | 11.6071 ms |
| 26.1.2 NeoForge 0.8 | 900.24 | 226.63 | 114.15 | 20.8036 ms |

| 分支 / 阶段 | 平均 FPS | 1% low | 0.1% low |
| --- | ---: | ---: | ---: |
| 1.20.1 静止 | 808.60 | 163.61 | 119.88 |
| 1.20.1 转向 | 840.30 | 202.42 | 148.64 |
| 26.1.2 静止 | 934.69 | 296.24 | 146.25 |
| 26.1.2 转向 | 865.80 | 193.68 | 97.84 |

两段采集均持续获得焦点，失焦重启次数为 0，帧样本中的物品实例数始终为 10000，结束快照中阴影实例数为 17030，没有 OpenGL 错误。所有采样帧均无缓存更新或队列积压，因此这两组仅反映默认复用路径，不能评价重建预算性能。

平均 FPS 为帧数除以累计帧间隔；1% / 0.1% low 为最慢 `ceil(帧数×比例)` 帧的平均帧时间再取倒数。没有同版本 0.7 的新 A/B 样本，不把跨引擎、跨 Java 的绝对 FPS 差异归因为移植优化。

## 干扰与限制

每约 2 秒记录一次进程和 GPU 状态，CPU 的 100% 表示一个核心的等效执行时间。

| 采样中的占用 | 1.20.1 | 26.1.2 |
| --- | ---: | ---: |
| 游戏 Java CPU 均值 | 52.92% | 88.88% |
| PixelSky 主进程 CPU 均值 | 31.61% | 25.77% |
| GPU 利用率均值 | 90.73% | 89.86% |
| GPU 时钟范围 | 2475–2490 MHz | 2475–2475 MHz |
| GPU 温度范围 | 74–75°C | 76–77°C |

1.20.1 采样时 Explorer 及多个无头浏览器进程出现显著活动；26.1.2 采样中途出现 ffmpeg 编码，最高约 1851% 单核等效占用。全部 PID、峰值、窗口时间和原始文件哈希保留在 JSON。结果不能证明长期稳定，也不支持按这些 low 帧直接判断优化幅度。

1.20.1 曾有一段平均 786.59 FPS 的迁移中间样本，之后补充了 NBT 兼容检测；该样本没有作为最终构建的成绩。

## 功能回归与发布包

- 两分支极小正预算下均观察到队列跨帧推进，期间完整保留 10000 个物品和 17030 个阴影；切换到 0 后队列正确清空，恢复默认 2 ms。
- 1.20.1 直接修改已缓存物品的 NBT 内容后，重建计数从 3 增至 4，确认不经过 `setTag` 的原地修改也能触发刷新。
- 三个版本均通过 `gradlew.bat build --offline`。1.20.1 发布包通过重混淆、Mixin refmap 与 UTF-8 元数据检查；三个 Jar 均确认未包含测试辅助代码。
- 26.1.2 测试使用独占全屏，排除了无边框模式与挂机限帧带来的环境差异。测试设置只存在于独立工作树的运行目录。
- 视频工作保留在主工作区，不切换主工作区分支，也不参与此次提交。

发布 Jar 集中在本地 `releases/0.8/`：`carbon-1.20.1.8.jar`、`carbon-1.21.1.8.jar`、`carbon-26.1.2.8.jar`。构建哈希、逐帧数据路径、场景快照与占用汇总见 [results.json](results.json)。
